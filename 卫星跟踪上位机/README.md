# RK3568 卫星跟踪上位机

这是重新设计的 Windows 上位机。程序保留现有 RK3568 转台网关和 HZZT-2-3kg AA 协议，不修改板端程序，界面只保留两个主要工作区：

1. **转台控制**：状态监视、定点、机械回零、0°/90°天顶姿态、查询和安全停止。
2. **卫星任务跟随**：由 TLE 和观测站位置预报过境，选择过境窗口后按实时时间连续计算方位/俯仰并驱动转台。

## 运行

程序已随附 MIT 许可的 `sgp4 2.27` 运行库，直接双击 `启动卫星跟踪上位机.bat` 即可。`安装依赖.bat` 仅用于需要从 Python 包源更新依赖时使用。

也可以在 PowerShell 中运行：

```powershell
cd E:\RK3568\卫星跟踪上位机
python main.py
```

默认网络参数与当前系统一致：

- RK3568：`192.168.1.101:20003`
- 上位机：`192.168.1.102:20003`
- 每个 UDP 数据报承载一帧原生 AA 协议，不增加其他封装。

如需临时修改地址：

```powershell
python main.py --gateway 192.168.1.101 --gateway-port 20003 --local 192.168.1.102 --local-port 20003
```

## 操作流程

### 转台定点

1. 连接 RK3568，等待界面显示有效转台状态。
2. 确认故障栏为“正常”。
3. 输入方位和俯仰，点击“执行定点”。
4. 随时可点击顶部“安全停止”。

程序只允许方位 `0～360°`、俯仰 `0～90°`。没有有效状态、状态超时或存在故障时，不允许发送运动命令。定点后 1.2 秒没有收到新状态会自动停止。

### 机械回零

“机械回零 0°/0°”执行以下流程：

1. 检查通信、状态时效和故障码。
2. 发送停止命令，取消正在执行的卫星任务。
3. 发送方位 `0°`、俯仰 `0°`定点命令。
4. 持续读取状态；两轴角度误差不超过 `0.2°`且速度不超过 `0.2°/s`时判定到位。
5. 到位后发送停止并锁定；60秒未到位、状态丢失或出现故障时自动停止。

机械回零使用转台已保存的编码器零点。它不会搜索限位开关，也不会重新写入零点；如果物理零位与状态中的 `0°/0°`不一致，应先由维护人员按厂家流程校准零点。

### 卫星任务跟随

1. 输入两行 TLE。
2. 输入观测站纬度、经度和海拔。
3. 设置最低跟踪俯仰角（例如 `10°`）和预报时长。
4. 点击“计算可跟踪过境”。
5. 从表格选择一次过境，点击“启动选中过境任务”。

任务状态机为：

```text
等待过境 -> 到达 AOS 且俯仰达到阈值 -> 150 ms 连续定点跟踪
         -> 低于阈值或到达 LOS -> 停止转台 -> 任务完成
```

因此，启动一个未来任务不会让转台提前运动；卫星未过境或低于最低俯仰角时不会下发定点命令。任务执行中如果状态反馈超过 2 秒未更新、收到故障码、网络异常或轨道计算异常，程序立即发送停止帧并进入“异常停止”。

修改 TLE、观测站、阈值或预报时长后，必须重新计算过境，避免旧过境窗口和新参数混用。

## 设计结构

```text
satellite_tracker/
  protocol.py   AA 帧构造、校验和状态解析
  transport.py  UDP 收发线程，只通过队列向界面传递事件
  orbit.py      SGP4 外推、ECEF/ENU 转换、方位俯仰计算
  passes.py     过境搜索、阈值交点和最大俯仰细化
  tracking.py   与界面/网络无关的跟踪状态机
  app.py        Tkinter 界面和安全联锁
```

与参考程序相比，轨道算法、过境预报、跟踪状态机、设备协议和界面被拆开；跟踪状态机可独立测试，后台线程不直接操作 Tk 控件。

第三方 `sgp4` 的许可证见 `THIRD_PARTY_SGP4_LICENSE.txt`。

## 测试

无需连接设备即可运行协议和状态机测试：

```powershell
cd E:\RK3568\卫星跟踪上位机
python -m unittest discover -s tests -v
```

测试覆盖协议帧、15/16 字节状态帧、校验错误、过境交点/峰值细化以及“等待—跟踪—离境停止”流程。上机前仍应在清空机械运动范围后进行低风险联调。
